# Provenance check: can we tell people what's real at least 80% of the time?

A test for the Provenance HUD idea: a display over any image that says whether it's AI-made, and admits when it doesn't know. The bar we set on Nov 10 2026: **right at least 80% of the time when it gives an answer**, and "don't know" otherwise.

It runs three kinds of check on a folder of images whose answers are known, and reports how often each one gives an answer and how often that answer is right. It reports original files and re-shared copies separately, because social media strips most metadata.

| Check | What it reads | Runs where | Cost |
|---|---|---|---|
| Metadata and signed labels (`check_metadata.py`) | C2PA signed origin labels ("Content Credentials"), the IPTC "made by AI" tag, generator settings saved in PNGs (Stable Diffusion, ComfyUI), generator names in software tags. Camera details are recorded but never decide the answer, since they're easy to fake | Locally | Free |
| Free detectors that guess from the pixels (`detectors.py`) | Four models: three popular ones on Hugging Face, plus Community Forensics (CVPR 2025, trained on images from thousands of generators) | Locally, on the Mac's GPU | Free |
| Google's watermark (`gemini_check.py`) | Uploads each image to the Gemini web app and asks it to check for SynthID. There's no public API, so the script drives a real Chrome window | Google's servers, using a logged-in Gemini account | Free, but every image goes to Google |

The report then combines them into the three levels the display would show: **Confirmed** (a label, tag or watermark says so), **Likely** (the best detector, only when it's confident enough to stay above 80%), and **Don't know**.

## Step 1: collect the images

Each image sits in the folder that matches its known answer. Most of the collecting is automated:

| Folder | Filled by | What it gets |
|---|---|---|
| `images/real/direct/` | `collect/wikimedia.py real 60` | Random Wikimedia Commons photos with camera details, taken 2000–2020, before AI images were hard to spot. Commons keeps uploaded files byte for byte, so the metadata is intact |
| `images/ai/direct/` | `collect/wikimedia.py ai 60` | A few files from each of Commons' "Images generated by …" categories for current tools: ChatGPT, GPT Image, Gemini, Nano Banana, Imagen, Midjourney, Flux, Firefly, Meta AI, Grok, Ideogram, Seedream, Qwen, Reve, Recraft and others. Whatever metadata the uploader kept is still there |
| `images/*/reshared/` (files starting `rs_`) | `collect/reshare.py` | One copy of every original, rotating through three simulations: Instagram-style (metadata removed, 1080 px, quality 78), WhatsApp-style (1600 px, quality 60), and a phone screenshot taken in Chrome |
| `images/*/reshared/` (files starting `fc_`) | An agent reading fact-checks | Viral images that AFP, Reuters, Snopes and others ruled on, saved as the copy that circulated, without the fact-checker's markings |
| any folder | You, by hand | Optional: your own phone photos in `images/real/direct/`, or images you generate yourself in `images/ai/direct/` |

Every collected file has a row in `collect/sources_*.csv` saying where it came from, and the report carries that through, so any wrong answer can be traced to its source. Files added by hand show as "added by hand".

```bash
cd image-test
.venv/bin/python collect/wikimedia.py real 60
.venv/bin/python collect/wikimedia.py ai 60
.venv/bin/python collect/reshare.py
```

- **Run the collectors one at a time.** Wikimedia throttles fast requests, sometimes with a 10-minute wait. The script waits it out.
- **How many:** 200 images is the target. With 50 images in total, a measured 80% could really be anywhere from about 67% to 89%. With 200 it narrows to about 74%–85%.
- **Privacy:** only public images, or your own photos. No photos of friends or family. The `images/` and `results/` folders stay on this machine.

## Step 2: run the local checks

```bash
cd image-test
.venv/bin/python run.py
.venv/bin/python report.py
```

The first run downloads the detector models (about 1.2 GB). Results are cached, so adding images and re-running only checks the new ones. The report is written to `results/report.md`.

## Step 3 (optional): add Google's watermark check

Log in once, by hand, in a Chrome window that uses its own profile (folder `.gemini-profile/`), not your everyday Chrome:

```bash
.venv/bin/python gemini_check.py --login
```

Then run everything including the watermark check:

```bash
.venv/bin/python run.py --gemini
.venv/bin/python report.py
```

It waits 8 seconds between images to stay under Gemini's limits, so 200 images take a while. Replies are saved in `results/gemini.json`. Any reply marked `unparsed` didn't follow the answer format, so read it there.

## What's been checked so far (Nov 10 2026)

- **Metadata:** correct on all seven sample files in `fixtures/`: two real photos, one signed C2PA test image, and four made-up files (an AI tag, Stable Diffusion settings, camera details only, no metadata at all).
- **Detectors:** all four load and run. On the sample real Canon photo (`fixtures/A.jpg`), two detectors said AI with 99–100% confidence and two said real. That disagreement is the reason for the test.
- **Pipeline and report:** a dry run on 23 throwaway images (crops of the sample files) went end to end. Those results mean nothing, because the images were crops of the same three files.
- **Gemini script:**
  - Tested: typing a prompt and reading the reply, on a logged-out page.
  - Not tested: uploading, which needs a login. Gemini switches upload off when logged out. The upload button selector came from the live page on Nov 10, but expect to fix it once logged in.

## What's weak

- **Simulated re-sharing is cleaner than the real thing.** Real apps may also crop, add borders or re-compress more than once. The fact-checked viral images are the closest thing to real conditions, and the report shows them separately ("By where the images came from").
- **Commons AI images are what uploaders chose to share.** Some will have had metadata stripped or been edited before upload, and some categories lean toward illustrations rather than photo-like images. Real photos from before 2021 may also be easier for detectors than recent phone photos, which are heavily processed by the phone.
- **Fact-check verdicts are taken as the answer.** The agent records the article for each one, so any doubtful one can be checked.
- **Gemini's answer is a chatbot reply, not a tool result.** It may guess instead of running the watermark check. Its replies are kept, so they can be checked.
- **"Not found" from Gemini doesn't mean real.** It only means Google's tools didn't make it, so the report never counts it as an answer.
- **Signed labels aren't checked against the official C2PA list of trusted signers yet.** A label that's valid but self-signed counts the same as one from Adobe or OpenAI. Adding that list is the next improvement if signed labels turn out to matter.
- **Images only.** Video would need frames sampled from it.

## Files

| File | What it is |
|---|---|
| `run.py` | Runs every check on every image and writes `results/results.csv` |
| `report.py` | Turns that into `results/report.md` |
| `check_metadata.py`, `detectors.py`, `gemini_check.py` | The three kinds of check. Each also runs on its own: `.venv/bin/python check_metadata.py some.jpg` |
| `fixtures/` | Sample files for checking the code works. Not test data |
| `vendor/commfor/` | Model code copied from [Community Forensics](https://github.com/JeongsooP/Community-Forensics) (MIT licence). Only `models.py` is used |
| `.venv/` | Python environment. Rebuild with `uv venv .venv --python 3.11 && uv pip install --python .venv/bin/python -r requirements.txt` |
